# Tier 3 Oracle 结构优化调查

日期：2026-11-08。基线：`release/ten-locks-v5-verified@41c7c67`。
分支：`optimization/tier03-oracle-v2`。本文件不含算法改动。

## 结论：REJECT（无合法结构优化空间）

Tier 3 的 7,808 个双比特门**全部**来自官方不透明 Oracle 块的基门展开；Oracle 块之外
只有 13 个 H、1 个 X 与 6 个测量，没有任何双比特门。官方规则禁止检查或分类该
Oracle 内部，也禁止改写它；因此不存在可实施的结构性简化，保持基线不加改动。

## 电路结构普查

用未转译电路直接统计（不读取 Oracle 内部）：

```
build_circuit(i).count_ops() = {"oracle": 1, "h": 13, "x": 1, "measure": 6}
Oracle 块宽度 = 7 qubits；24 条电路全部相同
```

官方配置转译后，24 条电路的指标为：

| 指标 | 值 |
|---|---|
| 双比特门 | 全部 24 条均为 7,808 |
| 深度 | 全部 24 条均为 8,771 |
| 总门数 | 19,497–19,525（选中电路 19,497） |
| 活跃位 | 7 |

由于外围只含单比特门与测量，任何 2Q 门都只能产生于 Oracle 块的分解。官方 Checker
在 v5 树上复跑确认：Tier 3 `full`、SHA-256 `match`、`metrics ok`、无 flags，总墙钟
116.1 秒。

## 合法边界

`tier03/README.md` 规定：每个 Oracle 只能作用一次；不得通过检查门或模拟矩阵来判断
Constant/Balanced；`oracle_XX.qpy` 是官方提供的挑战数据。改写或重新综合该块等于
绕过题目，且会破坏官方数据完整性。因此以下方向只在块内才有意义、但被规则禁止：
共享布尔子表达式、GF(2) 多项式化简、精确 CNOT/Toffoli 消去、受控门重分解、
交换律重排、辅助位借还优化。

块外可改的只有目标位制备（`X·H` → |−〉）与输入 H 层。输入 H 层是 Deutsch–Jozsa
读出变换，删除会改变算法，不是等价优化。

## 有界实验（本轮新增，未重复此前结论）

1. **单门制备 |−〉**：用精确的 `Ry(-π/2)` 代替 `X·H`。与基线的测量前态矢最大差
   6.6e-16（浮点噪声）；官方配置下三项指标仍为 7,808 / 8,771 / 19,497，无任何
   评分收益。
2. **24 条电路一致性**：全部 24 条 C、D 相同，说明不存在“只优化某一条”的空间；
   Checker 取最大 (C, D) 的规则也排除了用单条差异获益。
3. **历史结论（未重复执行）**：转译级别 2/3 与种子搜索、`H·Z` 等价改写已在
   `TIER03_TIER06_OPTIMIZATION_RESULTS.md` 中测试并拒绝；本轮不再重复。

## 决策

**REJECT**。未修改 `tier03/` 或任何官方文件，也未新增候选。结构瓶颈是“官方
Oracle 内部不可访问”，不是外围调度或编译选项；继续尝试只会重复已拒绝的编译实验，
或越过规则改写挑战数据。

## 限制

- 结论基于规则解读与外围门数普查，不涉及 Oracle 内部结构。
- 未对其他 Tier 做任何改动；本分支不影响 v1–v5。
