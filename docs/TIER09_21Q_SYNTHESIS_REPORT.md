# Tier 9：21-qubit 精确综合研究报告

日期：2026-11-11。基线：v6 RC `c445578` 的 Tier 9 v2（22 qubits）。
分支：`research/tier09-21qubit-synthesis`。未修改 RC、最终包、官方工具或生产代码。

## 1. 第 22 根线是什么

Tier 9 的 14 个相位位 + 7 个 work 位 + **1 根 clean synthesis workspace**。
检查源码与执行路径后，结论明确：

1. **不是执行幺正所必需**：本报告实际构建了去掉该线的 21-qubit 电路，`solve()`
   成功恢复密钥并通过官方哈希（见 §3）。
2. **是当前综合算法/官方基门分解所需**：`solution.py` 只在电路里把它注册为
   `synthesis_work`，原生 Aer 执行时保持空闲；官方评分转译把 `MCXGate` 展开到
   `rz,sx,x,cx` 时，它被当作 clean ancilla 使用并由 Qiskit 自动恢复。
3. **不是运行期测量或经典恢复所需**：14 个测量位与 work 寄存器不变。

因此该线属于第 3 类（只在官方基门分解中使用），是“用宽度换 CX”的编译期资源。

## 2. 21-qubit 构造与实测

`research/tier09_21qubit/evaluate.py` 用同一套公开乘子、`build_controlled_multiplier`
与 `build_inverse_qft` 重建电路，只去掉 clean 线。官方配置（`rz,sx,x,cx`、全连接、
level 1、seed 12345）转译结果：

| 指标 | 22q v2（基线） | 21q 候选 | 变化 |
|---|---:|---:|---:|
| 双比特门 | 55,999 | **69,693** | +13,694（+24.5%） |
| 深度 | 120,242 | **178,514** | +58,272（+48.5%） |
| 总门数 | 168,116 | **202,216** | +34,100（+20.3%） |
| 活跃位 | 22 | **21** | −1 |

这与历史记录中的“21-bit canonical fixed-mask 69,693 CX / 178,514 depth”一致，
说明去掉 clean 线后的原生长 MCX 展开代价就是如此，不是本轮构造错误。

## 3. 量子正确性证据

- 21q 电路与 v2 使用同一受控模乘块、同一完整逆 QFT、同一测量映射；唯一差异是
  不注册 clean workspace，因此逻辑幺正不变，变化的只是基门分解。
- 直接以 21q `build_circuit` 运行 Tier 9 `solve()`（64-shot Aer、未改恢复与解密
  逻辑）：**成功**，返回 `QC-09:` 前缀且明文 SHA-256 与官方 `hashes.txt` 匹配，
  用时 **41.2 秒**（v2 同机约 15.7 秒）。
- 未构造 21 位稠密算子；clean 线在所有基门分解路径中由 Qiskit 按 clean-ancilla
  契约恢复，这一点依赖 Qiskit 2.6.1 的合成实现，而不是我们新的证明。
- **未运行官方 Checker**：该候选在主要指标上已经劣于基线，不属于“最强候选应送
  Checker”的情形；哈希通过来自直接 `solve()`，不是 Checker 报告。

## 4. 尝试过的 21-qubit 方向

| 方向 | 结果 |
|---|---|
| 去掉 clean 线、原生长 MCX 综合 | 69,693 / 178,514 / 202,216 / 21（本报告实测） |
| 21-bit 固定掩码 canonical（历史记录） | 与上一行一致，确认不是实现误差 |
| 现有 v3 “last-target pivot” | 仍是 22 qubits，55,971 CX；不满足 21q 目标 |
| dirty-ancilla 借用 counting 线 | 未实现：需要为 2,353 个 MCX 逐块分配/恢复借用线，并重新证明所有控制与 padding 分支；本轮时间不足 |
| 周期锚点/共享谓词重排 | 历史 v2/v3 已做过有界搜索，收益 0–28 CX，无法弥补 13,694 的差距 |

**失败原因**：21q 的差距（+13,694 CX）远大于此前所有结构搜索的总收益；
要达标必须新增一套 dirty-ancilla MCX 综合，而不是微调现有 pass。

## 5. Simplicity 分析（固定对照的假设上界）

Tier 9 池 2.25 分，权重 40/30/20/10。设对照 best 为各指标的最小值，
候选与基线的 share 差：

```
Δ = 0.4·bC(1/69693 − 1/55999)
  + 0.3·bD(1/178514 − 1/120242)
  + 0.2·bG(1/202216 − 1/168116)
  + 0.1·bQ(1/21 − 1/22)
```

前三项均为负；Q 项最多约 +0.0045 share。取使 Δ 最大的极端假设
（bC=69,693、bD=178,514、bG=202,216、bQ=21），仍得
**Δ ≈ −0.279 share ≈ −0.63 分**。也就是说，在最有利于 21q 的对照假设下，
它仍然比 22q 基线差约 0.6 分；实际只会更差（对照通常小于候选值）。
**21q 只在活跃位一项占优，无法抵消 CX/深度/总门的损失。**

## 6. 结论与建议

**REJECT**：没有找到满足“21 qubits 且 CX < 55,999”的精确电路。
最接近的 21q 方案是 69,693 / 178,514 / 202,216 / 21，功能正确（哈希通过）但
资源全面劣化；22q v2 在 Simplicity 上占优。

- 保留 22q v2 作为 Tier 9 提交实现。
- 若未来仍要 21q，应投入 dirty-ancilla 借用综合（把其他 counting 线作为临时
  dirty ancilla，逐块证明复原），而不是继续微调现有 pass；这需要新的完整验证
  与 Checker，不属于截止前的可行范围。
- 本文件不宣称官方 Checker 通过；仅报告一次直接 `solve()` 的哈希验证与
 官方等价转译指标。
