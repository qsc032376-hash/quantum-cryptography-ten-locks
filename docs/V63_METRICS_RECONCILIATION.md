## 2. Hash Seed、遍历顺序、进程状态及随机性

- 对Tier 5与Tier 6公开构建器，用Hash Seed **0、1、42** 分别启动新进程；另在同一进程连续构建／转译3次。保留全部8个工作进程的结果；指标与count_ops一致，未观察到这些变量引发差异。这些是纯转译探针，没有新增Aer执行。Tier 6探针为公开默认搜索构建，不冒充测量校准后的实际选路。
- Tier 5的GF(2)处理顺序来自`circuit.data`，wire集合显式排序、消元选择确定；没有找到该用户代码中的随机遍历选择。对该basis的Euler候选分派检查只返回`ZSXX`，排除了“该pass在多个Euler basis间按集合遍历顺序选择”的具体解释。没有将这点泛化成所有Qiskit pass均被形式化证明确定。
- **Tier 5没有显式设置Aer seed。** 该采样随机性按批准代码保留；其唯一评分电路在测量前已经编译，采样不会选择另一条评分电路。Tier 6使用606及607+batch，Tier 7使用707/708。没有改代码注入新seed。
- 因此本轮是三次固定环境的新执行，**不是三组独立随机种子的统计可靠性试验**。量子采样seed和transpiler seed也没有混为一谈。
- 原生浮点阈值、编译器构建及Rust线程行为是尚未完全隔离的可能机制。没有以理论阈值或合成小电路测试冒充实际差异的根因证明。

## 5. 差异目前定位到了哪一层

Tier 5批准提交的 `docs/v63-evidence/compiler-replay.json` 记录历史原生编译计数：`rz=12301, cx=11000, sx=4862, x=300`。本地对应计数中前三项相同，**x=250**。历史与本地最终总门数相差50，准确对应这50个X门；两边官方评分后的CX均为10,950。

这将Tier 5差异缩小到具体门类型，但没有历史有序门列表，不能断言是哪25对X被抵消，也不能据此声称跨环境相位等价已独立证明。Tier 6/7的历史原生count_ops未在限定检查的21份证据JSON中找到，暂只能确认CX不变、差异落在单比特门总量／深度。

前次审计已找到同源码历史指标变化：Tier 6曾得到本地同一组5,691／8,680；Tier 7曾出现153／527与154／536；Tier 5的28,363／28,413差异也在批准集成报告中写明。历史先例不是根因证明。当前能够排除批准文件变化、官方配置变化、错误使用build模板及在已测试范围内的Hash Seed／进程状态扰动；仍没有隔离历史Python补丁、平台、原生数学实现或编译线程行为中的具体触发因素。

## 6. 对Simplicity和提交合规性的影响

官方按实际有效电路计分，没有规定不同环境必须复现同一历史门数。`tools/rank.py`和`SCORING.md`要求FULL、真实测量参与求解、有效指标等条件；本轮全部通过，批准的真实量子算法源码和文件均未变化。hash通过不单独用作unitary等价证明，实际记录、来源检查及本地逐门比较是额外证据。

固定其他合格队伍指标，设每关Simplicity池为P、权重为w，正值竞争基线r下有 `S=P Σ w·min(v,r)/v`；官方零最优值分支也已检查。Tier 5/6的池各1.5分，Tier 7为1.875分；权重为CX 40%、depth 30%、gates 20%、qubits 10%。
