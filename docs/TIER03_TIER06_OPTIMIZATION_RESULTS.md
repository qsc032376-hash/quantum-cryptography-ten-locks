## Tier 3：REJECT，未改代码

Tier 3 每关 24 条 7-qubit 电路，2Q 门几乎全部来自官方不透明 Oracle 的基门展开；
外围只有目标位 X/H、6 个输入 H 与测量。按任务列出的方向逐一做了有界实验：

1. **编译器级别**：level 2/3 把 2Q 门从 7,808 降到 7,680（−128，−1.64%），但深度
   从 8,771 升到 10,453（+19.2%），总门数升到 22,847（+17.2%）。按 Simplicity
   权重（0.4/0.3/0.2）估算为净负收益，且 24 条电路中选中的仍是更差的组合。
2. **转译器种子**：seed 0–7 全部得到完全相同的 7,808 / 8,771 / 19,497，说明该
   Oracle 块对种子不敏感，没有可挖掘的调度差异。
3. **外围等价改写**：把目标位准备从 `X·H` 改成 `H·Z`，指标逐项相同；Qiskit 2.6.1
   无 `measure_x`，无法省掉最后 6 个 H。没有可测收益。

未读取、分解或重写 Oracle 内部，未用经典分类结果替代量子电路，因此 Tier 3 保持
基线，不做提交。

## Tier 6：ACCEPT

只改 `submissions/team3/tier06/solution.py` 中 `_simulate()` 的预转译级别（1 → 2）。
Oracle、Diffuser、12 轮 Grover、标记集合、测量与经典筛选逻辑均未改动。

| 指标 | v4 基线 | 候选 | 变化 |

| 2Q 门 | 3,000 | 3,000 | 0 |
| 深度 | 5,883 | 5,715 | −168（−2.86%） |
| 总门数 | 9,534 | 8,752 | −782（−8.20%） |
| 活跃位 | 22 | 22 | 0 |

原因：level 2 消除了 level 1 之后残留的冗余 RZ 层；Checker 在自己固定的 level 1
配置下重新转译记录电路，仍得到上述数值。seed 0–15 结果完全一致。

另测“先把 phase oracle 与 diffuser 各自综合成基门再组合”的方案：总门数 8,738
（比接受方案少 14 门，0.16%），2Q 与深度相同；收益过小且会改动 Oracle 构造与
求解耗时，按“无实际收益不强改”原则拒绝。
